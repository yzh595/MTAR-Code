This repository implements **MTAR** and its teacher-guided extension, **MTAR++**. The conference-paper link above refers to the preliminary MTAR work; the MTAR++ results below are from the extended manuscript.

## Highlights

- **Spatial foresight supervision.** Predict spatially related future tokens rather than relying only on next-token supervision.
- **Pretrained generative knowledge transfer.** MTAR++ predicts current- and future-position features from an existing pretrained and frozen autoregressive generative teacher.
- **Dual-path semantic dropping.** Reduce redundant student and teacher computation while retaining complete teacher target groups at supervised anchors.
- **Unchanged inference.** Remove auxiliary training components and use the original next-token head and autoregressive decoding procedure.

## Method Overview

### Multi-token foresight supervision

MTAR uses multi-token prediction (MTP) to predict ground-truth codebook indices at spatially related future positions. MTAR++ replaces these discrete auxiliary targets with multi-feature prediction (MFP), predicting current- and future-position features from a pretrained and frozen generative teacher while retaining next-token prediction. The default teacher is NAR-XL. Both frameworks incorporate token-level contrastive regularization to encourage consistency under feature perturbations and discriminability among token representations.

  <img src="assets/mtarpp_foresight_overview.png" width="960" alt="Complete multi-token foresight supervision diagram: (a) MTAR multi-token prediction of future codebook indices; (b) MTAR++ multi-feature prediction of current and spatially related future features from a frozen generative teacher.">
  <br><sub>(a) Multi-token prediction in MTAR. (b) Multi-feature prediction in MTAR++. Both retain next-token supervision.</sub>
</p>

### Dual-path semantic dropping

Semantic dropping uses offline patch-level scores to preferentially retain semantically rich patches, reducing redundant computation while preserving original spatial positions. MTAR++ also selects teacher tokens in groups covering all current and future targets. Feature supervision is computed at the intersection of retained student positions and selected teacher-group anchors.

## Results

### ImageNet 256 × 256

All entries below use 300 training epochs. Parameter counts include student-side training auxiliaries for MTAR and MTAR++, excluding the frozen teacher and tokenizer. Auxiliary heads are not required at inference.

| Model | Training parameters | FID ↓ | IS ↑ |
|:--|--:|--:|--:|
| LlamaGen-B | 111M | 5.46 | 193.61 |
| MTAR(B) | 138M | 4.50 | 213.96 |
| MTAR++(B) | 124M | 4.22 | 230.27 |
| LlamaGen-L | 343M | 3.80 | 248.28 |
| MTAR(L) | 387M | 2.85 | 271.41 |
| MTAR++(L) | 358M | 3.09 | 267.18 |

### Training quality and efficiency

MTAR(B) and MTAR(L) provide **1.27× and 1.39× training-time speedups** at the same 300-epoch budget. After only 50 epochs, MTAR++(B) and MTAR++(L) reach FIDs of **5.35 and 3.53**, beating their corresponding 300-epoch LlamaGen baselines with one-sixth as many iterations.

  <br><sub>Speedup = total training time of the matching 300-epoch LlamaGen baseline / total training time of the evaluated configuration.</sub>
</p>

### Learning with limited student data

MTAR++(B) achieves lower FID than MTAR(B) and LlamaGen-B across the evaluated student data scales. With **300k student images**, it reaches **FID 6.53**, compared with **7.29** for LlamaGen-B using all **1.281M images**.

## Quick Start

### 1. Environment

Use a [LlamaGen](https://github.com/FoundationVision/LlamaGen)-compatible PyTorch environment. The shared requirements target Python 3.10, PyTorch 2.2.1 with CUDA 12.1, and torchvision 0.17.1.

```bash
git clone https://github.com/yzh595/MTAR-Code.git
cd MTAR-Code
pip install -r requirements.txt
```

See the [DINOv3 extraction instructions](dinov3/README.md) for semantic-score dependencies and model access.

### 2. Data preparation

Extract aligned VQ tokens, class labels, and DINOv3 semantic scores:

```bash
CUDA_VISIBLE_DEVICES=0,1 bash scripts/extract_dinov3_scores.sh \
    /path/to/imagenet/train \
    /path/to/imagenet256_features \
    /path/to/vq_ds16_c2i.pt
```

Semantic scores are computed offline once and reused during training. The output directory contains:

```text
imagenet256_features/
├── imagenet256_codes/
├── imagenet256_labels/
└── imagenet256_scores/
```

### 3. Checkpoints

Prepare the following local checkpoints before training or sampling:

| Checkpoint | Used for |
|:--|:--|
| LlamaGen VQ-16 tokenizer | Discrete token extraction and image decoding |
| Pretrained NAR-XL generative teacher | MTAR++ training only; passed as `TEACHER_CKPT` |
| Trained MTAR / MTAR++ student | Sampling and evaluation |

The training launcher does not download the teacher automatically. Student sampling does not require the teacher checkpoint.

### 4. Train MTAR++

The following launcher uses a LlamaGen-L student, a frozen NAR-XL teacher, MFP(C,R,B), TCR, and dual-path semantic dropping. Student dropping is 50% for the first 80% of training; teacher dropping is 50% throughout training.

```bash
METHOD=MTAR++ \
TEACHER_CKPT=/path/to/NAR-XL.pt \
CUDA_DEVICES=0,1 \
bash scripts/train_c2i.sh \
    /path/to/imagenet256_features \
    /path/to/mtarpp_results
```

The default MTAR++ launcher targets the large model. Its student feature layer is set to 24; reproducing a base-model configuration also requires matching the student layer and other scale-specific settings, not just changing `GPT_MODEL`.

<details>
<summary><strong>Train the conference MTAR model</strong></summary>

The default MTAR launcher trains LlamaGen-B for 300 epochs with MTP, TCR, and 50% student semantic dropping during the first 80% of training, followed by full-sequence training.

```bash
METHOD=MTAR CUDA_DEVICES=0 bash scripts/train_c2i.sh \
    /path/to/imagenet256_features \
    /path/to/mtar_results
```

</details>

Shared defaults include batch size 256 and learning rate `1e-4`. The launcher enables student EMA. Additional settings are available in [scripts/train_c2i.sh](scripts/train_c2i.sh).

### 5. Sampling and evaluation

Sample 50,000 images from an MTAR++ large checkpoint using the unchanged autoregressive inference path:

```bash
GPT_MODEL=GPT-L CUDA_VISIBLE_DEVICES=0 \
bash scripts/sample_c2i.sh \
    /path/to/mtarpp_large_checkpoint.pt \
    /path/to/vq_ds16_c2i.pt \
    1.80 \
    ./fid_samples \
    50000
```

Use `GPT_MODEL=GPT-B` and guidance 1.85 for MTAR++ base. The reported MTAR base and large results use guidance 2.00.

Evaluate the generated NPZ file:

```bash
EVAL_CONDA_ENV=lla bash scripts/evaluate_c2i.sh \
    /path/to/VIRTUAL_imagenet256_labeled.npz \
    /path/to/generated_samples.npz
```

See [evaluations/README.md](evaluations/README.md) for the ADM TensorFlow evaluation environment.
